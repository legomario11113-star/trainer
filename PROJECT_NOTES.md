## Что это
Офлайн-веб-приложение (PWA) — дневник тренировок с кабинетом тренера.
- **Сайт:** https://legomario11113-star.github.io/trainer/ (GitHub Pages, ветка `main`, корень репозитория).
- **Репозиторий:** `legomario11113-star/trainer`. Владелец — Артём (аккаунт GitHub `legomario11113-star`).
- **Цель:** заменить бумажные блокноты в зале. Тренер заводит клиента, пишет ему план, отправляет ссылку; клиент записывает подходы (вес × повторы, запас, отдых), тренер видит историю.
- Пользователи сейчас: Артём (тренер-админ и сам клиент «Я»/«Артем»), Надежда (клиент, исторический id `her`). Дальше — знакомые / клиенты реального тренера.

## Модель данных (`S` в app.js)
- `names: {clientId: имя}` — список клиентов (у клиента на устройстве — только он сам).
- `plans: {clientId: {week, rule, days:[{id, label:"Пн", title, exercises:[{name, type, sets, reps, weight, rest, hint, test}]}]}}`
  - `type`: `wr` вес×повторы, `r` повторы, `t` время (сек), `cardio` мин/км/уровень. `rest` — секунды. `weight` — целевой вес строкой (подсказка в поле кг у клиента).
- `sessions: [{id, ts, profile:clientId, date, dayId, dayTitle, ex:[{name, type, note, sets:[{w, r, rir, t, min, km, lvl, rest}]}], feel, note}]`
- `measures: [{id, ts, profile, date, weight, waist, note}]`
- `drafts: {clientId: черновик текущей тренировки}` — только локально, не синхронизируется. Отдых: `set.restStart` (идёт отсчёт) → `set.rest` (секунды, зафиксировано).
- `library: [{name, type, rest, hint, group}]` — библиотека тренера. `group` — группа мышц из `GROUPS` в coach.js (Ноги, Ягодицы, Спина, Грудь, Плечи, Руки, Пресс и кор, Кардио, Другое); для новых/старых упражнений угадывается по названию (`guessGroup`).
- `deleted: {id: ts}` — «надгробия» удалённых тренировок/замеров.
- `meta: {plansTs:{id}, nameTs:{id}, deletedClients:{id:ts}, libraryTs}` — время изменений для слияния.
- `ui: {profile, tab, day:{id: dayId}, coach:{view:"list"|"client"|"library", id}}`

## Хранилище и безопасность (sync.js)
- Один **секретный gist** на аккаунте тренера. Токен GitHub — classic, только scope `gist`.
- Файлы в gist:
  - `trainer.admin.enc.json` — индекс тренера (клиенты, удалённые клиенты, библиотека). Ключ = **главный ключ** (32 байта, создаётся при «Создать хранилище», хранится только на устройствах тренера и в «Ссылке для своих устройств»).
  - `trainer.<clientId>.enc.json` — данные клиента (имя, план, тренировки, замеры). Ключ клиента = `SHA-256(главный + "trainer/client/" + id)`; исторические: `me` → главный ключ, `her` → `SHA-256(главный + "trainer/her")`.
- Шифрование AES-GCM в браузере. На GitHub только шифротекст.
- **Ссылки:** `…/trainer/#join=TRN3.<base64url JSON>` (часть после `#` не уходит на сервер).
  - тренер: `{t, g, m}`; клиент: `{t, g, c:id, k:ключ клиента, n:имя}`. Старые `TRN1`/`TRN2` понимаются (совместимость).
  - При установке «на экран Домой» манифест подменяется так, чтобы `start_url` содержал ссылку с ключом (iPhone хранит данные иконки отдельно от Safari).
- **Слияние:** тренировки/замеры объединяются по `id` (побеждает больший `ts`), удаления по «надгробиям», план/имя/библиотека — кто новее по времени.
- Таймаут запросов к GitHub — 20 с, кнопки показывают «Создаю…/Подключаю…».
- **Известный риск прототипа:** в ссылке клиента лежит токен тренера (scope gist). Чужие данные клиент прочитать не может (нет ключа), но технически может удалить/испортить файлы в gist. Для своих людей — приемлемо, для чужих клиентов — нет → см. «Переход на настоящий сервер».
- **Потеря главного ключа = потеря облачных данных.** Страховка: два устройства тренера + «Ссылка для своих устройств» в надёжном месте + «Сохранить копию» (JSON).

## Как пользоваться (коротко)
1. Тренер: «Ещё» → «Синхронизация» → токен → «Создать хранилище» → сохранить «Ссылку для своих устройств».
2. «Тренер» → «Добавить клиента» → составить план (названия из библиотеки подставляют тип/отдых/подсказку) → «Сохранить план» → «Ссылка для клиента» → отправить.
3. Клиент открывает ссылку (на iPhone в Safari → «На экран Домой»), видит только свой план, записывает подходы. ✓ — подход + отсчёт отдыха, ✓ ещё раз — отдых зафиксирован.
4. Тренер видит тренировки клиента после синхронизации (сама при открытии / сохранении).

## Принятые решения (почему так)
- PWA вместо нативных приложений — одна ссылка для Android и iPhone, без сторов.
- GitHub Gist как хранилище — бесплатно, без новых регистраций, работает из России. Это **прототип**; хранилище изолировано в `sync.js`.
- Классический присед со штангой Артёму не даём (шея/техника) — это в скилле `personal-trainer`, не в коде.
- Внешних зависимостей нет, кроме SheetJS (вложен в репозиторий). Без сборки — обычные файлы.

## Переход на настоящий сервер (когда появятся чужие клиенты)
- Заменить **только `sync.js`** на модуль с тем же внешним интерфейсом: `Sync.profiles`, `Sync.isAdmin`, `Sync.on`, `syncNow()`, `schedule()`, `clientLink(id)`, `section()`, `handle()`, `copyText()`.
- Варианты: Supabase/Firebase (быстро, но западные — риск ограничений и 152-ФЗ) или свой VPS в РФ (API + БД).
- Нужны: аккаунты тренера и клиентов (вход по ссылке-приглашению/паролю), права «клиент видит только себя», согласие на обработку персональных данных (вес, замеры, самочувствие — данные о здоровье), хранение в РФ, резервные копии.
- Миграция: тренер выгружает всё (резервная копия JSON) → загрузка в новую базу; клиентам разослать новые ссылки.

## Как тестировать (для Claude)
Живой сайт из среды Claude недоступен (прокси). Тесты — локально: `python3 -m http.server` + Playwright (`/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell`), GitHub API подменяется через `context.route('https://api.github.com/**')` (POST/GET/PATCH /gists). Проверять: старый формат → новый, тренер → клиент → тренировка → тренер видит, клиент не видит чужих. Деплой: `git push` в `main` → GitHub Actions «pages build and deployment» (~1 мин).
